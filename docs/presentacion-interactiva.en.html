Presentation and confirmation of guidelines

What the system guarantees

  • 12 accounts (1 main + 11 subaccounts), each running an independent strategy.
  • Unbreakable rule: zero orders without a Stop Loss; the guard rejects the order before it is sent.
  • Capped total exposure: at most equity × leverage per subaccount, counting what is already open (new).
  • Drawdown cut-off: a subaccount that falls more than 25% from its peak stops opening positions for 14 days (new).
  • MCP on Antigravity with the official SDK 2.2, in stateless HTTP mode.
  • The same code in every phase: backtest → dry_run → demo → live.

Step 2 — Account router and guard

Guard lab

The same rules that risk/guard.py applies to every order (engine and MCP server), and the position sizing from risk/sizing.py.

Would this order pass?

Orders that reduce or close a position, and spot sells, do not need an SL. The spot leg of SUB6 is explicitly exempt because it is the hedge.

Risk-based sizing

Quantity = equity × risk ÷ |entry − SL|. If the quantity is below the market minimum, the order is not sent. Since October 2026 the notional cap also subtracts what is already open. The original design rounded it up to 0.01 BTC and multiplied the risk by up to 2.5×.

What the test found and how it was fixed

fixed

Hidden leverage in SUB2 and SUB11

The size cap was applied per position: with 3 positions open at once, exposure reached 9× equity instead of 3×. Now the cap counts what is already open, and the backtester requires margin just like the exchange.

fixed

SUB7 chained 4% losses in bear markets

The grid was rebuilt every day and each breakout cost up to 4%: −94% over the full cycle. Now it is not set up if the daily EMA20 falls more than 3% in 5 days.

fixed

SUB6 opened and unwound pairs in a loop

With the daily kill-switch active on one wallet, it opened the allowed leg, the other leg was rejected, and it unwound the first, paying fees on every scan. Now it checks both wallets before opening.

new

Drawdown cut-off on every subaccount

If a subaccount falls more than 25% from its peak, it opens no positions for 14 days (configurable). SUB8, the DCA, is excluded because it accumulates on dips by design.

Going to production

Recommended road to live trading

  1. backtest

    12 to 24 months per strategy, with historical fees (0.06% taker), slippage and funding. Runs the same code as live.

  2. dry_run

    Real prices and simulated orders. The logs and the order journal are reviewed.

  3. demo

    Bitget Demo Trading API keys on each subaccount, 2 to 4 weeks per strategy.

  4. live

    Requires CONFIRM_LIVE_TRADING=yes. Keys without withdrawal permission and with an IP whitelist. Start with a few strategies and little capital.

There is a separate roadmap for launching the PUDA token in El Salvador: docs/lanzamiento-el-salvador.html.
